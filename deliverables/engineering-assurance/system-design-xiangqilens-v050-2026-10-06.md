## 🏗️ 设计要点（Archi 主导，Zhen 汇编）

### 需求 1：走棋模式互斥

**决策**：`QButtonGroup` **三态单选**（`关闭` / `预览模式` / `启动走棋`），替换原来两个可同时勾选的
`QCheckBox`。辅助方法 `_auto_mode()` / `_set_auto_mode()`。
**关键不变量**：`_load_auto_config` 里 `mode` 只接受 `off`/`dry`，读到 `real` 一律降级为 `dry`
—— 保证「启动后永远不会自动开始点鼠标」。旧 `automove.json` 的 `dry_run` 布尔自动迁移。

### 需求 2：开局库（应用层）

**决策**：官方 Pikafish 无库能力 ⇒ 在应用层做「先查库，命中用库着，不命中交引擎」。
双格式：`.xqb`（社区标准，SQLite，**按 key 精确查询、只读打开**）+ `.txt/.json`（自研线路库）。
配套 `tools/build_book.py` 用引擎自动生成 xqb，形成闭环。
**接口契约**：`OpeningBook(path)` / `.probe(fen)` / `.pick(fen, mode, legal_check)`。
**关键约束**：库 key 不含轮次 ⇒ 库着必须过**严格**合法性校验。

### 需求 3：动画抑制

**决策**：不做「加长 sleep」，做**可判定的帧间运动闸门** —— 拉正图缩成 160×144 灰度图，
统计**变化像素占比**（非平均绝对差，因为「吃」字只覆盖盘面中间一小块）。
占比超阈值 → 暂停识别；静止达 `settle_ms` → 恢复。自动走棋读同一闸门状态。
**必要兜底**：最长抑制时长（默认 5s）后强制放行一帧，防持续动画把识别卡死。

### 需求 4：自动接盘

**决策**：终局判定以 **`has_no_legal_moves`（真合法）为唯一可靠信号**；「长时间停滞」作
**默认关闭**的兜底；**明确排除**「引擎报绝杀分」这一信号（理由见下）。
按钮位置由用户**标定**，存**相对窗口原点**偏移。

## 🚨 两条关键事实纠正

### ① 官方 Pikafish 二进制没有开局库功能

直接运行 `engines/pikafish.exe` 并发送 `uci`，拿到的**全部**选项：

```
Debug Log File / NumaPolicy / Threads / Hash / Clear Hash / Ponder
/ MultiPV / Move Overhead / nodestime / UCI_ShowWDL / EvalFile
```

没有任何 `BookFile` 之类的库选项（Stockfish 官方也没有，只有 Polyfish 等分支有）。
所以「对照皮卡鱼的开局库功能」只能落在**应用层**。

### ② `cchess.is_valid_iccs_move` 是伪合法校验（项目旧注释有误）

`cchess/board.py:227` 的 docstring 原文：「**只进行最基本的走子规则检查**，不对每个子的规则
进行检查，以加快文件加载之类的速度」——它**不检查自将 / 将帅照面**。

实测：`R3k3R/4R4/9/9/9/9/9/9/9/4K4 b` 双车杀局面，黑将被红车将军，
`is_valid_iccs_move` 对 `e9d9` / `e9f9` / `e9e8` 三个**送将**着法**全部返回 True**。

**影响**：`app_backend.is_legal_move` / `enumerate_legal_moves` 都建立在它之上，
**不可用于终局判定**；项目文档/注释里「会完整校验……自将等规则」的说法是错的（已改正）。

**对策**（新增两个严格接口）：

| 函数 | 实现 |
|---|---|
| `is_strict_legal_move(fen, iccs)` | 伪合法之上再要求「走完不自将、不照面」（落子 + `next_turn()` + `is_checking()`） |
| `has_no_legal_moves(fen)` | 真终局判定，直接用 cchess `no_moves()`（内部逐着做自检） |

> `BoardTracker` 的演化校验仍沿用旧的伪合法 `is_legal_move` —— 它作为单帧噪声过滤器够用，
> 收紧它有回归风险，**本次刻意未改动**（已记入项目 MEMORY.md 的「已知陷阱」）。

## 📌 TL;DR（第二轮）

- ① **`.obk` 格式完整逆向并支持**：用真实的 `云霄剑诀7.5.obk`（170986 条）验证通过，
  还发现并兼容了**生成工具的 double 存储坑**。
- ②③ **自动接盘重做为模板匹配**：从「固定坐标」改为「截图框选录模板」，
  并会先自动关掉挡路弹窗。用真实截图验证相似度 **1.000**。
- ③ 的直接原因已查明：面板显示 **「未标定」** —— 从未录过模板，自然不会点击。
- 新增 142 条断言（原 87 → 142），20 项回归全绿。

## ① obk 开局库格式（逆向结论）

| 项 | 结论 |
|---|---|
| 容器 | SQLite；表 `bhobk(id, vkey, vmove, vscore, vwin, vdraw, vlost, vvalid, vmemo, vindex)` + `idxkey(vkey)` |
| 键 | cchess 的 Zobrist（`cchess.zhash_data`）：起始局面（红先）= `7101337512282506414`，正是库中第 1 条 `vkey`。**键含行棋方**（红先异或 `z_redKey`）→ 无 xqb 那种轮次歧义 |
| 着法 | `(起点偏移 << 8) \| 终点偏移`，偏移 = `0x33 + (9 - FEN行)*16 + 列`；ICCS = `chr(97+列) + str(行取反)` |
| 验证 | 起始局面 `0xAAA7`=`h2e2`（炮二平五）；炮二平五后（黑先）`0x3A59`=`h9g7`（马8进7）；走库 14 层全命中且全合法 |
| ★ 坑 | 键值 ≥ 2^63 时生成工具按 **IEEE double** 存进 `vkey`，SQLite 索引查不到。把该 double 的 8 字节原样解包可**无损还原**原键 → 程序先走索引、查不到再 `CAST(vkey AS REAL)=?` 全表扫（**4.9ms**） |

**影响**：这是**社区实际流通**的格式（此前我按 GitHub 上的 xqbook 做的 `.xqb` 只是
小众格式）。现已两种都支持，`.xqb` 保留。

## ②③ 自动接盘重做

**根因**：面板显示「未标定」→ 从未录模板 → 不点击。但即使录了，**固定坐标也点不到** ——
天天象棋打完一局会连弹「段位升级」「财源广进」「获得徽章」，把结算面板挤走甚至盖住。

**改法**：

| 旧 | 新 |
|---|---|
| 在目标窗口上单击一次，记一个**坐标** | 在弹出的**截图**上拖拽**框选**，存成**模板 PNG** |
| 点固定坐标 | `cv2.matchTemplate` 找按钮，点其中心 |
| 弹窗挡路就失败 | 先找「关闭弹窗」模板逐个关掉，再找「再来一局」（最多 8 轮） |

**要点**：

- 在本程序截图上框选 → **完全不会误触目标窗口**。
- 模板读写走 `imencode/imdecode` —— `cv2.imread` 在 Windows 上**不支持非 ASCII 路径**
  （应用目录可能含中文），会静默返回 None。
- 抓帧会改写 `source.rect`，用完**立即还原**，否则自动走棋的坐标换算会用到陈旧矩形。

**真实截图验证**（用芒果老师提供的 4 张截图）：

| 模板 | 匹配图 | 相似度 |
|---|---|---|
| 「再来一局」（录自结算面板） | 结算面板 | 1.000 |
| 「再来一局」 | 获得徽章弹窗（按钮被部分遮挡） | 1.000 |
| 「关闭弹窗」✕（录自财源广进） | 财源广进弹窗 | 1.000 |
| 「关闭弹窗」✕ | 结算面板 | 1.000（且坐标相同） |

→ 天天象棋各类弹窗的 ✕ **位置一致**，一个模板即可关掉全部。

## ① 「框选没反应」根因

| 项 | 内容 |
|---|---|
| 现象 | 对局结束、已停止运行，点「框选『再来一局』按钮」无任何反应 |

## ② 新局 · 自动判断我方执子

**判断原理**：识别模型给的 4 个角是**内容语义**的

**己方**摆在画面下方 ⇒ 谁的两角在下面（y 更大），谁就是我方。
**与「红方先手」无关，所以开局红方还没动子也能判。**

**质量门（必需）**：真实截图实测 8 张里有 3 张关键点退化（A0 在画面底部而 A8 在
顶部、整组点跑到画面外、四点重合）。程序要求「同边两角大致等高」+「棋盘高度足够」
+「四点都在画面内」，不满足则**拒绝判断并继续重试**，不瞎猜。

**新局做的事**：清空局面跟踪（局面/轮次/计数/终局标记）+ 武装自动判断。
对局还在匹配中、棋盘没出现时自动重试。

**去掉「先手」+ 轮次自纠**：`BoardTracker` 新增**双方合法性自纠** ——
差分着法对当前轮次不合法、但对另一方合法时直接纠正轮次并采信。
前提是 `cchess.is_valid_iccs_move` 会校验「起点格棋子颜色 == 行棋方」，
同一差分着法不可能对红黑双方同时合法。⇒ 初始轮次只影响「第一次走子之前」。
