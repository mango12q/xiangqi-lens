# XiangQiLens v0.3.0

把棋盘从屏幕里「读」出来，交给 Pikafish 分析，并在棋盘上画出推荐走法箭头。

**不含自动走子** —— 只给建议，落子由你自己操作。

![界面](https://raw.githubusercontent.com/mango12q/xiangqi-lens/main/docs/screenshot.png)

---

## 下载与运行

下载 `XiangQiLens-v0.3.0.zip`，解压后双击 **`XiangQiLens.exe`**。

**无需安装 Python 或任何依赖** —— 运行时已打包进 exe。

> ⚠️ 请**解压后整目录使用**，不要只把 exe 单独拷出来。exe 需要同级的
> `xq_research/` 目录提供识别模型与引擎（约 95MB）。

系统要求：Windows 10 / 11（64 位）。

## v0.3.0 更新内容

这一版把右侧分析栏做成了典型象棋引擎 GUI 的样子：**参数可调、多主变例、可持续加深**。
同时修掉了两个一直悄悄生效的 bug —— 其中一个让「胜率显示」从发布起就没真正走引擎输出。

### 新增：引擎参数面板（实时热改）

右栏新增可折叠的「**引擎参数**」面板，改动**立刻作用于正在跑的分析**，不需要停止再开始：

| 参数 | 说明 |
|---|---|
| **线程 Threads** | 1 ~ CPU 逻辑核数 |
| **哈希 Hash** | 置换表大小，16 ~ 4096 MB |
| **多主变例 MultiPV** | 同时输出 1 ~ 8 条主变例 |
| **落子延时 Move Overhead** | 传给引擎的时钟补偿 |
| **显示胜/和/负 (WDL)** | 是否请求引擎输出 WDL 概率 |
| **清空置换表** | 一键 `Clear Hash`，换局面后立刻重新搜索 |

下面还有一个「**高级（引擎全部可调项）**」区：握手时读取引擎实际支持的 UCI 选项列表，
按 `spin / check / combo / string` 动态生成控件 —— 不同版本的 Pikafish 选项不同，
这里永远跟着引擎走，不用改代码。

> 热改的实现方式：**停止当前搜索 → 下发选项 → 用当前局面重开搜索**。
> 引擎在搜索过程中不响应 `isready`，所以不能在搜索中途改参数；暂停-重开是无损的
> （棋盘局面不重新识别，直接复用）。
>
> 连续拖动 SpinBox 时命令会自动合并，只应用最后一次，不会把引擎反复停/启抖崩。

### 新增：多主变例 (MultiPV)

原来的「候选着法」表升级为 **真 MultiPV**：直接解析引擎 `info` 行的 `multipv` 字段，
同时展示 N 条完整主变例。

| # | 分数 | 胜率 | 深度 | 中文主变例 | ICCS |
|---|---|---|---|---|---|
| 1 | +1.23 | 我方 61% | 26 | 炮二平五 马8进7 马二进三 … | h2e2 h9g7 h0g2 … |
| 2 | +0.45 | 我方 52% | 24 | 马二进三 … | h0g2 … |
| 3 | +0.31 | 我方 50% | 24 | 兵七进一 … | c3c4 … |

棋盘上除了绿色粗箭头（最佳着法），各条主变例的首着会用蓝色细箭头标出。

### 新增：持续加深

顶栏勾选「**持续加深**」后，引擎对当前局面 `go infinite` 一直算下去，
主变例随深度实时刷新；不勾选则每次识别到新局面按「思考」时间分析一次。

流式刷新只重绘箭头与右栏文字，**不重传棋盘图像** —— 引擎每秒刷新多次也不会掉帧。

### 新增：引擎崩溃自愈

引擎进程意外退出（被杀、崩溃）时，程序会自动重建引擎，**并用当前局面重开搜索**，
分析不中断。重建失败时限频重试，不会永久静默。

### 修复：胜率显示从未真正使用引擎的 WDL 输出

两个叠加的 bug，导致从 v0.1.0 起「胜率」一直是**本地估算值**，而不是引擎算出来的：

1. **`UCI_ShowWDL` 传值格式错误** —— 选项只认小写字符串 `true`，而代码传的是 Python 的
   `True`，拼接后变成 `setoption name UCI_ShowWDL value True`，被引擎**静默忽略**。
   实测开启前后 info 行里的 `wdl` 字段数量都是 0。现在改传 `"true"`，引擎正常输出
   `wdl 72 917 11` 这样的三元组。
2. **WDL 的视角搞反了** —— `wdl` 是**当前行棋方**视角，不是红方视角。实测红方多一车时，
   红方行棋输出 `wdl=(1000,0,0)`、黑方行棋输出 `wdl=(0,0,1000)`。
   原来直接按红方视角解释，黑方走棋时胜率会**完全反过来**。现在统一先换算到红方视角再显示。

顺带修掉了 `MultiPV` 表里 `lowerbound` / `upperbound` 边界行的处理 ——
这类行的 PV 是截断的中间结果，原来覆盖上去会把完整主变例换成两三步残段，现在会跳过。

### 修复：朝向判断（v0.2.1 起）

> 如果你是从 **v0.2.0** 升上来的，这条同样适用 —— v0.2.1 没有单独发 Release，已并入本版。

v0.2.0 认为「执黑时画面上下颠倒，必须翻转矩阵」，于是按「我方执子」把 90 格矩阵旋转 180°。
**这是错的**：识别模型的关键点本身就是内容语义的（黑方两角 / 红方两角），
透视拉正流程已经把黑方底线摆到 row 0 —— 无论哪一方在画面下方，模型输出都已是标准朝向。

再翻一次会把局面翻反（黑将落到 row 9），被「局面严格校验」判成 `黑将在九宫外 (9,4)`，
每帧都挡下，状态栏只会一直刷「局面变化无法解释，已挡下」。

**现在矩阵不再按「我方执子」翻转**，只在遇到模型输出异常（黑将真的在下方）时自检兜底翻转一次。
「我方执子」现在只影响胜率视角与左栏显示图朝向。

### 优化

- **棋盘图像缓存** —— 引擎持续加深时高频刷新不再重复做 `cv2 → QImage` 转换，开销显著下降
- **中文着法缓存** —— `(局面, 主变例)` 命中时直接复用，实测单条主变例回放约 1.4ms，
  5 条线 20Hz 下约占单核 14%，缓存后同一条线连续多轮不变时不再重复计算
- **退出时清理引擎进程** —— 关窗口会确保子进程被回收，不再留下孤儿进程占着 CPU

## 功能总览

| 能力 | 说明 |
|---|---|
| **后台截图** | 用 `PrintWindow` 截取窗口，**不要求窗口可见、可被遮挡**；失败自动回退屏幕抓取 |
| **走法箭头** | 绿色粗箭头 = 最佳着法，蓝色细箭头 = 候选变化，直接画在棋盘上 |
| **多主变例 (MultiPV)** | 引擎真实 MultiPV，中文 + ICCS 双列 |
| **引擎参数面板** | 线程 / 哈希 / MultiPV / 落子延时 / WDL 实时热改 + 高级项动态生成 |
| **持续加深** | `go infinite` 锁定局面持续加深，主变例实时刷新 |
| **崩溃自愈** | 引擎意外退出自动重建并恢复分析 |
| **胜率显示** | 引擎 WDL 输出（本版起才真正生效），视角按我方执子自动换算 |
| **中文着法** | `h2e2` → `炮二平五` |
| **轮次推断** | 局面差分 + 引擎着法合法性自纠 |
| **朝向自适应** | 识别角点是内容语义的，自动得到标准朝向，不需要人工翻转 |
| **四道识别闸门** | 任何一道不过都不会把垃圾局面送进引擎 |
| **失败可见** | 左栏显示识别程序实际看到的棋盘 |

### 四道识别闸门

每帧识别结果依次通过：

1. **棋盘几何校验** —— pose 模型在画面没棋盘时也会输出 4 个点且常退化成一条线
2. **局面严格校验** —— 将帅各一、数量上限、九宫、照面（`cchess` 对缺子局面太宽松）
3. **棋规校验** —— `cchess` 构造与着法规则
4. **演化校验** —— 新局面必须能由上一局面走一步合法着法得到，挡住单帧误识别

## 实测数据

识别性能（683×1253 窗口，RTX 4070）：

| 配置 | pose | cls | 完整单帧 |
|---|---|---|---|
| CPU 推理 | 13.8ms | 872.5ms | 979ms |
| DirectML | **4.1ms** | **128.0ms** | **170ms** |

引擎：Pikafish 2026-09-06，开局 `depth 26` 约 1.2 秒。

### 参数默认值怎么定的（i7-12800HX 实测）

本机是 8 P 核 + 8 E 核 / 24 逻辑核的混合架构，实测线程数与 NPS：

| Threads | NPS | 相对 1 线程 |
|---|---|---|
| 1 | 916,808 | 1.00x |
| 4 | 3,842,282 | 4.19x |
| 8 | 6,666,382 | 7.27x |
| 16 | 10,346,205 | 11.29x |
| 24 | 12,166,291 | 13.27x |

NPS 随线程线性涨，但**「到同一深度的耗时」并不线性下降**（混合架构 + HT 影响），
且本程序还要同时跑 ONNX 识别占 CPU。所以默认取 **Threads = 8**（正好吃满 8 个 P 核）。

哈希实测：64 MB 深搜时 `hashfull` 直接 999/1000（置换表被挤爆，等于白扩线程），
256 MB 舒适（657/1000），1024 MB 无收益。所以默认 **Hash = 256 MB**。
长时「持续加深」或高 MultiPV（≥5）可临时提到 Hash=512 MB、Threads=12~16。

## 已知限制

- **识别会偶发出错**：模型在个别棋子/皮肤上会误判（例如红傌读成红炮）。
  闸门 4 能挡住瞬时错误，但若误判连续稳定出现，兜底机制会在 6 帧后采信它。
- **窗口不能最小化**：最小化时截图拿不到棋盘。程序会检测并提示。
- **仅 Windows**：截图、DPI 与窗口状态检测依赖 Win32 API。
- **不含自动走子**：这是刻意设计，只做识别与建议。
