# XiangQiLens v0.4.0

把棋盘从屏幕里「读」出来，交给 Pikafish 分析，在棋盘上画出推荐走法箭头。
这一版新增**可选的自动走棋** —— 轮到我方时模拟鼠标点击落子。

**默认关闭，且默认处于「预览模式（只算不点）」**，需要你显式关闭预览才会真正点击。

![界面](https://raw.githubusercontent.com/mango12q/xiangqi-lens/main/docs/screenshot.png)

---

## 下载与运行

下载 `XiangQiLens-v0.4.0.zip`，解压后双击 **`XiangQiLens.exe`**。

**无需安装 Python 或任何依赖** —— 运行时已打包进 exe。

> ⚠️ 请**解压后整目录使用**，不要只把 exe 单独拷出来。exe 需要同级的
> `xq_research/` 目录提供识别模型与引擎（约 95MB）。

系统要求：Windows 10 / 11（64 位）。

## v0.4.0 更新内容

### 新增：自动走棋（模拟鼠标点击落子）

开启后：识别到**轮到我方**且局面稳定 → 取引擎最佳着法 → 模拟鼠标点击
「起点 → 终点」替我落子。对手仍在真实平台上下棋，本程序不动对方棋子。

#### 实现方式

与 [babalae/better-genshin-impact](https://github.com/babalae/better-genshin-impact)
的 `MouseEventSimulator` 同一路线：`user32!SetCursorPos` 移动光标 +
`user32!mouse_event` 发左键按下/抬起。

**纯 Win32 用户态调用：无内核驱动、无内存注入、不读写目标进程内存。**

比 BGI 更稳的一点：BGI 用 `MOUSEEVENTF_ABSOLUTE` 归一化坐标（只覆盖主显示器），
本项目改用 `SetCursorPos` 的虚拟桌面物理坐标，天然支持多显示器与负坐标。

**零新增依赖、零打包配置改动** —— 只用 `ctypes` + 已在包内的 `win32gui`。

#### 坐标链（复用识别链路，未改识别）

```
引擎着法 h2e2
  → move_arrow(warp_mat)          反投影得到「原截图坐标」src_from / src_to
  → + 抓帧时窗口矩形原点 (l, t)     = 屏幕物理坐标
  → SetCursorPos + mouse_event
```

进程启动即设 Per-Monitor V2 DPI 感知，截图坐标与屏幕物理坐标一致，无需缩放换算。

#### 安全闸门

只有**全部**满足才会点击：

| 闸门 | 说明 |
|---|---|
| 只走我方 | `side_to_move == my_side` |
| 起点是我方棋子 | 防止轮次误判时动到对方的子 |
| 局面稳定 | 已通过四道识别闸门 + 连续 N 帧一致 |
| bestmove 属于当前局面 | 不是上一次搜索的残留 |
| 同局面同着法只点一次 | 防重复点击 |
| 冷却时间 | 两次落子最小间隔（默认 1.5s） |
| 窗口可用 | 未最小化、能置于前台 |
| **落点未被遮挡** | `WindowFromPoint` 校验两点都确实在目标窗口上，防止点到别的程序 |
| 抓帧后窗口未移动/缩放 | 否则透视矩阵失效，放弃本次 |
| 保险丝 | 连续走子数上限（默认 200） |

其它保障：

- 点击未生效会自动重试，超过上限**自动停止并提示**；
- 「紧急停止自动走棋」按钮只关自动走棋，不终止识别；
- 「启用」开关**不持久化** —— 每次启动都从关闭状态开始；
- 参数保存在应用目录的 `automove.json`（已加入 `.gitignore`）。

#### 思考时间

自动走棋强制使用**限时搜索**（`go movetime`）。原因是 `go infinite` 永远不返回
确定的 `bestmove`，无法用于落子 —— 所以开启自动走棋时「持续加深」会自动置灰。

#### 使用步骤

1. 右栏展开「自动走棋」面板，保持 **「预览模式（只算不点）」勾选**；
2. 勾选「启用自动走棋」，点「开始」；
3. 观察右栏/状态栏显示的「将点击的着法与屏幕坐标」，确认坐标落在正确交叉点；
4. 确认无误后取消「预览模式」勾选，此时才会真正点击。

> 首次使用建议先跑 `python tools/test_click_coord.py` 生成
> `analysis/click_preview.png`（在原截图上标出点击点，不点击），肉眼核对坐标。

#### 限制

- 点击是**前台物理点击**：会抢占真实鼠标，目标窗口必须**可见且能置于前台**。
  窗口被遮挡或无法置前时会跳过本次并提示（识别本身仍可后台进行）。
- 部分界面只认「拖拽」而非「两次点击」，可在面板切换落子方式；
  若界面要求鼠标「移过去」才响应悬停，可把「移动插值步数」调到 4~8。

### 改进：「当前建议」栏的胜率表述

去掉了「我方胜率 62% · 和 21% · 对方 17%（我方大优）」这种相对视角的长句，
改为**只报占优的一方**：

| 局面 | 现在显示 |
|---|---|
| 红方占优 | `红方优势，红方胜率约 62%` |
| 黑方占优 | `黑方优势，黑方胜率约 58%` |
| 均势 | `均势（红 50% / 黑 48%）` |

红/黑胜率相差不足 10 个百分点即判为均势；引擎未给出 WDL、退化为按分数估算时，
末尾会附 `（估算）` 标记。

胜率现在一律按**红/黑方绝对视角**给出，不再随「我方执子」换算
（该选项仍保留，作用只剩左栏棋盘朝向）。右侧 MultiPV 表的「胜率」列
未改动，仍是「我方视角」的百分比。

### 新增：工具脚本

| 脚本 | 用途 |
|---|---|
| `tools/test_click_coord.py` | 坐标验证：算屏幕坐标并标在原图上，**不点击**（`--selfcheck` 纯函数自洽） |
| `tools/test_autoclick.py` | 真实点击验证：`--dry-run` / `--move-only` / `--yes` 三档 |
| `tools/test_automove_gates.py` | 安全闸门单元测试（13 个场景，不点击） |
| `tools/test_automove_e2e.py` | 端到端干跑（默认预览，`--real` 才真点） |

## 与 v0.3.0 的兼容性

- 识别、引擎、棋规、UI 均无破坏性改动；不开启自动走棋时行为与 v0.3.0 一致。
- `app_backend.ScreenSource` 新增 `rect` 属性（抓帧时记录窗口矩形），
  供自动走棋换算屏幕坐标；`move_screen_points()` 为新增函数。
- 新增 `app_input.py`（纯 ctypes 鼠标注入）。
- `app_backend.format_winrate()` 的输出文案有变化（只报优势方，红/黑绝对视角）；
  函数签名不变，`my_side` 参数保留但不再影响输出。
- 「我方执子」下拉框不再影响胜率视角，只控制左栏棋盘朝向。
- 版本号：`app_backend.__version__` = `0.4.0`。
