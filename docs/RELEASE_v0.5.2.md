# XiangQiLens v0.5.2

以**可靠性与工程基建**为主的一版：修掉自动走棋与引擎客户端里若干「平时不发作、
一发作就点错鼠标 / 拿错着法」的缺陷，补齐测试与 CI，理顺打包链路。
**另有一处会改变你看到的行为**，见第 1 节。

---

## 1. ⚠ 默认值变化：MultiPV 由 3 改为 1

**MultiPV 不是「多搜几条线」，而是把同一份思考时间摊给 N 条主变例，每条都更浅** ——
而自动走棋要走的正是第一条。本机实测（`go movetime 1200`、Threads 2、Hash 256）：

| 局面 | MultiPV=1 | MultiPV=3 | 深度差 |
|---|---|---|---|
| 开局 | 深度 22 | 深度 20 | −2 层 |
| 中局 | 深度 32 | 深度 23 | **−9 层** |

所以默认改成 **1（最强单线）**。**要看候选变化 / 复盘研究**时，到右栏「引擎参数」
把 MultiPV 调高即可（面板里的说明也写清了代价）。

> 这一项直接影响棋力，是本版唯一会改变你既有观感的地方。

## 2. 自动走棋可靠性

全部是「异常路径才发作」的缺陷，平时看不出来：

| 缺陷 | 后果 | 修法 |
|---|---|---|
| `place_move` 异常时 `finally` 只还原光标、**不抬左键** | 鼠标永久停在按下态，桌面「拖动粘住」直到手动点一下 | 维护 `_btn_down` 标志，所有出口都过 `_release_if_down()` |
| `click_at` 丢弃 `move_to()` 的返回值 | `SetCursorPos` 失败时仍照点，落在**上一个光标位置**（别的窗口），绕过遮挡闸门 | 移不到位就抛异常，不点 |
| `MouseClicker.move_to(steps>1)` **恒返回 True** | 拖拽模式下每次移动都谎报成功，调用方无法补救 | 累积真实结果再返回 |
| `GetCurrentThreadId()` 未声明 `restype` | ctypes 默认有符号，与无符号 DWORD 比较；自挂接被 Windows 拒绝 → 置前失效、点击被跳过 | 声明 `restype = wintypes.DWORD` |

**新增「鼠标注入」选项**：落子点了没反应时（常见于 CEF / 微信小程序类界面）
可以换成 `SendInput`。此前这个后端在 `app_input` 里实现了、文档也承诺了，
但两处构造都没传 —— **只有手工跑测试脚本才能选到**，用户永远摸不到。

## 3. 引擎客户端（协议层）

| 缺陷 | 后果 | 修法 |
|---|---|---|
| `analyse()` 超时不发 `stop` | 引擎仍在跑，残留的 `bestmove` 会被**下一次搜索**当成新局面的结果（结果串味） | `try/finally` 包住，超时就 `stop()` + 等 `bestmove` + 排空队列 |
| MultiPV>1 时取**最后一条** PV 的分数 | 返回的是**最差那条**主变例的分数（实测 multipv 1 cp300 / 2 cp40 / 3 cp−1200 → 旧代码返回 −1200） | 只接受 multipv 1（或未标注）的分数 |
| `__EOF__` 哨兵只可消费一次 | 引擎死后第二次等待会**空转满超时**，且无法区分「引擎已死」和「没响应」 | 加 `_dead` 事件作为权威信号；实测第二次等待 1.01s → 0.00s |
| 引擎已死时 `send()` 抛裸 `OSError 22` | 报错看不出原因 | 改成明确的 `RuntimeError` |

## 4. 引擎进程生命周期：不会再留下孤儿 Pikafish

Windows 上**子进程不随父进程退出而终止**，所以关窗口、崩溃、被任务管理器结束时
Pikafish 都可能活下来 —— 它会和当前引擎抢 CPU 与内存，同样 `movetime` 的搜索
要少算好几层。

本版加了三层：

1. **Job Object**（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）：内核保证本进程一退出，
   其引擎子进程必被终止。这是**不依赖时序**的保证。
   实测：父进程 `os._exit()`（跳过所有清理）后 1 秒，子进程已消失。
2. `run()` **自己**在退出路径上收掉引擎，不再依赖 GUI 线程在正确的时刻调用
   `shutdown()`（`closeEvent` 的 `thread.wait(3000)` 超时后不会等它）。
3. 创建引擎后检查是否已收到停止请求，是就地收掉（原来这段窗口里创建的引擎无人关闭）。

## 5. 其它修复

- **运行日志改为追加**（原来每次启动覆盖）并超过 2MB 轮转成 `XiangQiLens.log.1`。
  崩溃详情另有 `XiangQiLens_crash.log`；这次补上的是**正常流程的轨迹** ——
  报障时最需要的「上一次跑到哪一步」不再被下次启动抹掉。
- **打包链路**：
  - `--paths` 从**未跟踪**的 `xq_research/` 改指入库的 `vendor/`。
    原来同一次发布里会塞进**两份不同版本的同一个模块**，且不会有任何报错。
  - 代码资产缺失时**硬失败**，不再静默回退到未跟踪目录。
  - 冒烟测试现在要求自检日志里出现 `[通过]`（原来只看退出码，
    一个**写不了盘**的 exe 也算通过）。
  - `--zip` 统一委托 `tools/make_release_zip.py`，直接产出带版本号的
    `XiangQiLens-v0.5.2.zip`，**不再需要手工改名**。
  - 构建时清掉上一轮生成的 `XiangQiLens.spec`（它写着绝对路径）。
- **图标入库**：`assets/icon.ico`（原创绘制，`tools/make_icon.py` 可重现，
  含 16~256 七个尺寸）。原来图标指向**另一个仓库**
  `../refs/chessboard/server/icons/icon.ico` —— 换台机器就静默丢图标。
- **清掉 6 处硬编码本机路径**（`diag_engine` / `repro_engine` / `test_wdl` /
  `patch_tracker` / `xq_vision.main()` / 启动器 bat）。
- **`app_book.py` 两个 SQLite 后端去重**：抽出公共的只读打开、权重算法、
  结果行解析与按局面缓存（原来各写一遍，改一处漏一处是必然的）。
  **obk 的全表扫兜底逻辑未改动。**

## 6. 测试与 CI

新增 **`tools/run_tests.py`**：跑遍 `tools/test_*.py` 并汇总成
**通过 / 跳过 / 失败** 三类。

约定：**环境不具备 ≠ 代码回归**。需要真实对局窗口、或需要识别模型与引擎
（它们不在仓库里）的测试，一律打印 `[跳过]` 并 `return 0` —— 见
`tools/_common.py` 的 `skip()`。理由很实际：**假红比没有 CI 更糟**，
它会训练维护者忽略 CI 失败。

新增 `.github/workflows/tests.yml`（Windows runner；**没有模型与引擎也应当是绿的**）。

新增 4 个测试脚本：

| 脚本 | 覆盖 |
|---|---|
| `test_engine_lifecycle.py` | 启动期间收到停止 → 新建引擎必须就地关闭；`run()` 退出路径自己收引擎；日志追加与轮转 |
| `test_build_chain.py` | `--paths` 必须指 `vendor/`、代码资产缺失硬失败、冒烟测试必须见到 `[通过]`、图标已入库且不指向别的仓库、zip 只有一条实现 |
| `test_gui_smoke.py` | 离屏构造主窗口；MultiPV 默认 1；「鼠标注入」贯通到 Worker / MouseClicker |
| （`test_model.py` / `test_align.py` 补上缺资源时的明确跳过） | |

**回归结果**：`python tools/run_tests.py` → **通过 22 / 跳过 6 / 失败 0**（28 个脚本）；
`python app_vision.py --selftest` → 全链路可用。

## 7. 本版**未**包含

识别主循环的单帧开销优化（都还没落地，不影响正确性）：

- 抓帧校验对整幅截图做 `astype(np.float32)`（实测 683×1253 要 **26.3ms**，
  占单帧 23%）；改 8 倍抽样后同一判据只要 0.30ms。
- BGRA→BGR 用花式索引而非 `cv2.cvtColor`（实测 3.23ms → 0.59ms）。
- `confirm=3` 的确认等待在**每一次**走子后都会重新触发，
  其中两次 `sleep(0.10)` 共 200ms 属于纯加时。
- 静止画面仍每帧全量推理（原始帧预闸门实测只要 0.90ms）。

另外 **obk 大库（如「屠龙」181MB）在未命中时仍会 `CAST(vkey AS REAL)` 全表扫**，
实测单次约 150ms；这是已知行为，本版未改。
