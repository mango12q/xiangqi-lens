# XiangQiLens v0.5.3

三块内容：**识别与抓帧快了约 7 倍**（单帧 ~165 ms → ~22 ms）、**两处会改变你操作习惯的
交互调整**（见第 1 节）、以及**四个开局库的实测评测**（含一份修好的可用副本）。

性能部分把第三轮、第四轮评审里**拖了三轮没落地**的四项一次性做完，并补上等价性回归测试。

---

## 1. ⚠ 会改变你看到的行为

### 1.1 动画抑制**默认开启**（v0.5.1 曾按需求默认关）

| 版本 | 默认值 |
|---|---|
| v0.5.0 | 开 |
| v0.5.1 ~ v0.5.2 | **关** |
| **v0.5.3** | **开** |

作用与代价：

- **好处**：天天象棋吃子时棋盘中间弹的「吃」字动画（以及落子动画、窗口刷新）期间
  **暂停识别**，不再把动画帧当成盘面 → 修掉「吃子时误识别 / 判断不出对方是否走子」。
- **代价**：画面必须静止达到「静置时长」（默认 400 ms）才恢复识别。表现为**启动后
  第一帧要多等 400 ms**、连续动画期间识别会推迟；最长抑制 5 s 有兜底，不会永久卡住。
- **不想要**：右栏「识别稳定（动画抑制）」面板里取消勾选「等画面静止后再识别」即可
  （面板现在默认展开，参数为静置 400 ms / 变化阈值 0.02）。

### 1.2 「新局」按钮**移除**，自动判断我方执子改到「分析」

原「新局」按钮实际只做两件事：停掉当前分析 + 准备自动判断执子。现在执子改成
**点「分析」就自动判**，按钮本身没有必要：

- **判据不变**：象棋客户端一律把己方摆在画面下方，按棋盘朝向判（开局红方还没动子也能判）。
- **判错随时改**：运行中「我方执子」下拉框**不再被禁用**，改了立刻经命令队列生效；
  **手动改过之后本次分析不再自动判断**，不会过几帧又被改回去。下一次点「分析」重新自动判断。
- **首帧轮次**规则（原「先手」下拉早已删除）：首帧盘面还是**初始局面** → 按规则「红方先手」；
  否则（中盘接手）→ 默认「**轮到我方**」。猜错有两层兜底：观察到第一次走子时做
  「双方合法性自纠」，自动走棋另有「开局却认为轮到黑方」的硬闸门。

**开新一局怎么办**：

- **打完一局直接开下一局 → 什么都不用点。** 棋盘一换，演化校验会把新盘面当成
  **「稳定新局面」接管**（同一个新盘面连续 **2 帧**一致即采信；连续 **6 帧**仍无法解释则
  **强制采信**并在状态栏提示「局面跳变且持续存在」），不会一直卡在「局面变化无法解释」。
- **想彻底清空上一局的残留**（局面 / 轮次 / 计数 / 终局标记）→ 点 **「停止」** 再点
  **「分析」**：每次「分析」都是全新的 `Worker` 与全新的局面跟踪，天然干净。

## 2. 性能：单帧 ~165 ms → ~22 ms（约 6 Hz → 约 44 Hz）

### 2.1 本轮最关键的一条：推理慢了 13~24 倍，因为**模型输入维度是动态的**

两个 ONNX 模型的输入声明里带动态轴（pose 是 `['batch',3,256,256]`，cls 是
`['batch',3,'height','width']`），而管线喂进去的尺寸其实**恒定**。带动态轴时
onnxruntime 的 DML provider 每帧走慢路径。用
`SessionOptions.add_free_dimension_override_by_name()` 把三个轴钉死后：

| 模型 | 动态维度 | 钉死后 | 加速 |
|---|---|---|---|
| `cls`（90 格分类） | 124.45 ms | **5.09 ms** | **24.4x** |
| `pose`（4 角点） | 2.29 ms | 1.03 ms | 2.2x |
| `XiangqiVision.infer` 整体（真实截图 1833×1256） | 121.6 / 123.3 / 123.9 ms | **10.1 / 8.7 / 8.8 ms** | **≈13x** |

CPU 版同样受益（180.6 ms → 50.7 ms）。

### 2.2 其余三项（第三轮、第四轮评审里一直未落地）

| 项 | 位置 | 改动 | 实测 |
|---|---|---|---|
| 抓帧校验整幅 `astype(np.float32)` | `app_backend.py` | 改 `img[::8, ::8]` 抽样（判据只是「不是全黑」） | 25.1 ms → **0.35 ms**（86x） |
| BGRA→BGR 花式索引 | `app_backend.py` | 改 `cv2.cvtColor(arr, cv2.COLOR_BGRA2BGR)` | 3.24 ms → **0.52 ms**（6.2x） |
| `confirm` 与「局面未变」共用一个 `sleep(0.10)` | `app_vision.py` | 两个条件**拆开**：确认新变化只 `sleep(0.005)`，稳态轮询才节流 | 每手省 **~200 ms** |

**单帧预算变化**：

| 阶段 | 改前 | 改后 |
|---|---|---|
| `_print_window`（含 BGRA→BGR） | 16.0 ms | ~12.6 ms |
| 抓帧校验 | 25~30 ms | 0.35 ms |
| `infer`（pose + cls） | 122 ms | **8.8 ms** |
| **合计** | **≈165 ms（约 6 Hz）** | **≈22.5 ms（约 44 Hz）** |

`python app_vision.py --selftest` 实测「识别 **22 ms/帧**」（原 ~170 ms）。

### 2.3 等价性证据与诚实边界

| 验证对象 | 规模 | 结果 |
|---|---|---|
| cls 输出 | 300 组输入（随机 / 近全黑 / 高对比 / 低对比） | argmax 不一致 **0**；最大绝对差 1.2e-6 |
| pose 输出 | 100 组输入 | argmax 不一致 **0** |
| 真实截图全链路 | 37 张 | `rows` **37/37 相同** |
| BGRA→BGR | 683×1253 / 1307×778 | **逐字节相同** |
| 抓帧校验抽样 | 40 张真实截图 + 3 张合成极端帧 | 回退判定 **0 张不一致** |

**边界**：固定维度后输出**不是逐位相同**，有 1e-6 量级浮点噪声（kernel 归约顺序不同）；
而决策量是 argmax，实测最低置信 0.22~0.80，离 1e-6 能翻转的边界差五个数量级。
另外新增一个失败模式：**覆盖值与实际喂入尺寸不符** —— ORT 对此抛 `InvalidArgument`，
且新增的 `assert_input_shape()` 会在**构造期**就报错，所以最坏表现是「一启动就报错」
而不是「悄悄识别错」。

## 3. 开局库实测评测（新增报告与工具）

新增 `开局库评测报告.md` 与 `tools/book_bench/`（21 个脚本，每个结论都有对应脚本与
`out/*.json` 原始数据；`out/` 属可重跑的中间产物，**不入库**）。

四个库在应用自己的 `OpeningBook` 代码路径下的实测结论：

| 场景 | 推荐 | 理由 |
|---|---|---|
| 一个都不改，直接选 | **云霄剑诀 7.5** | 唯一「打开就能用」：0 非法着法、不丢数据、查询 5 ms |
| 用生成的修好副本 | **先锋无敌 nn 库 241111** | 着法质量最高（平均 CPL 2.1、78% 与引擎最佳着完全一致）、开局第一手就是引擎最佳着 |
| 覆盖优先 | 最新屠龙商业库 | 覆盖最广（命中率 56.2% vs 40.7%），但**开局第一手会走「仕六进五」**（比最佳差 41 厘兵）、体积 237 MB |
| 不推荐 | 静香库 | 覆盖最低（11.5%），且全库权重几乎相同 → 选着等于随机 |

两个**静默失效**的坑（都在库里，不在应用代码里）：

- **先锋无敌**的着法字节序是反的（`(终点<<8)|起点`）→ 原库「装了等于没装」；
- **屠龙 / 静香**的 SQLite 索引有漏行 → 不兜底就静默丢数据（屠龙丢 50.5%，连初始局面都查不到）。

修好的副本已生成在 `开局库/_fixed/`（**不入库**，本机文件），**不需要改应用代码**，
在界面里直接选那个文件即可。应用层对应的三个缺陷（索引不兜底 / 字节序不自检 /
脏权重照走）**本版未修**，见第 5 节。

## 5. 本版**未包含**

| 项 | 内容 | 为什么没做 |
|---|---|---|
| N5 | **原始帧预闸门**（静止帧不推理，实测静止帧 165 ms → ~2 ms） | **有准确性取舍**：棋盘被弹窗遮挡时原始帧「没变」会跳过推理 → 需要保守阈值 + 强制重识别兜底，应与零行为变化档分开评估 |
| N6 / N7 / N8 | 开局库应用层三个缺陷（索引不兜底 / 字节序不自检 / 脏权重照走） | 本版用「选修好的库副本」规避，代码侧修复待排期 |
| N9 | 发布 zip 把 `.dll/.pyd` 当**已压缩格式**存（`tools/make_release_zip.py`） | 一行改动即可让发布包小 **~197 MB**（427 MiB → ~230 MiB），本版未改，故本版 zip 仍约 427 MiB |
| N11 | `run_tests.py` 没有「通过数下限」（全部跳过也打印「全部通过」） | 待排期 |
| N12 | `_fill_pv_table` 每次刷新重建全部表格项（20 Hz × N 条） | 待排期 |
| N13 / N14 | `requests` 未声明；`build_exe.py` 的 spec 清理写在构建**之前**（等于没清） | 待排期 |
